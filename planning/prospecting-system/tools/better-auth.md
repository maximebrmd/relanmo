# Better Auth — application authentication

**Status: required by the user.** Run the open-source library inside `apps/app`, backed by Neon through Drizzle. Authentication and application tenant authorization remain separate responsibilities.

## Package and route ownership

Put server configuration and session helpers in `packages/auth`, using `better-auth` and the official `@better-auth/drizzle-adapter`. Use `provider: "pg"` and pass the generated auth schema. The current documentation uses the separate adapter package; verify the pinned Better Auth/Drizzle versions together. [Official Drizzle adapter](https://better-auth.com/docs/adapters/drizzle).

Mount `/api/auth/[...all]` in `apps/app` using `toNextJsHandler` from `better-auth/next-js`. Export the React client from a distinct client entry point using `better-auth/react`. Server Components and commands obtain a verified session through the server API. The auth route stays on the customer application's origin; the separate webhook application needs no shared browser cookie. [Next.js integration](https://better-auth.com/docs/integrations/next).

## Implementation

1. Replace next-forge's Clerk wrapper, provider components, login pages, organization switcher and webhook handlers. Update every caller and environment key; deleting only the Clerk dependency is insufficient.
2. Start with verified email/password login, password reset and verification emails delivered by the Resend SDK. Add supported social sign-in later if needed. Store a strong `BETTER_AUTH_SECRET` and an explicit application base URL in server configuration.
3. Generate auth tables from the chosen Better Auth configuration and plugins. Incorporate the generated Drizzle schema into `packages/database`; review SQL generated by Drizzle Kit and apply it through the same release migration process as product tables.
4. Give auth tables an explicit namespace or names and adapter mappings. Better Auth's `account` record is an authentication identity; our `provider_accounts` record is a connected LinkedIn account. They must remain distinct.
5. Keep `tenants` and `memberships` as application-owned records. For the initial freelancer product, create a personal tenant transactionally and idempotently. Every protected operation verifies the session and current membership. An active tenant cookie or URL parameter alone grants no access.
6. Configure exact trusted origins, HTTPS cookies, expiration and revocation. Use the supported database rate-limit store across replicas and include its table in generated Drizzle migrations; per-process memory is inadequate for a multi-instance login service. Apply separate limits to custom server commands because direct auth server API calls do not receive the client-route limiter automatically.
7. Use Resend callbacks for verification/reset mail, with safe expiry and redirect handling. Do not log secrets or full authentication URLs.

Give the auth adapter a restricted server-only role for its auth tables. Tenant RLS applies to product tables; login must not require a tenant context before identity has been established. Worker roles do not need access to login sessions or credentials.

The core library is open source; hosting, database queries and email have costs already modelled. No per-user managed-auth subscription is assumed. [Better Auth repository](https://github.com/better-auth/better-auth), [email/password configuration](https://better-auth.com/docs/authentication/email-password), [rate limits](https://better-auth.com/docs/concepts/rate-limit).

## Validation

Verify registration, email verification, login/logout, expiry, reset, revoked sessions and cross-tenant access on the real application. Test several app replicas and a database outage. A proxy redirect is a navigation convenience; enforce authorization again in every server command. Check worker packages cannot import browser-only auth modules.

Stripe subscription state belongs to `packages/payments`. Do not add a second independent billing implementation through an auth plugin unless the design is deliberately changed.
